# module `concept`

- **Status:** implemented (MVP-α, A7)
- **Public API:** `index.ts` (the ONLY file other modules may import). Factory `createConceptModule` in `module.ts`.

## Layout
- `domain/` (pure): `title.ts` (cleanTitle, suggestion normalization, title material check), `transitions.ts` (CS3–CS9, CB2–CB8, CS2 stage table), `brief.ts` (working brief model, paths, provenance, hash), `question-set.ts` (`common@1` CQ-01~21 + 10a~d, required/conditional slots, field dependencies, value coercion), `slot-guard.ts` (INV-CON-03/04, conflicts 4.4, flips, dependencies), `change-proposals.ts` (proposal lifecycle), `auto-approve.ts` (자동 승인 decision), `next-question.ts` (3.5 selection, reserved buttons 900–907, logline/summary fallbacks), `checks.ts` (X-9 + CS3 blockers INV-CON-05/10/11/12/15), `turn.ts` (commit planners for turn / import / form edit), `proposal.ts` (zod: ConceptTurnProposal, import, check), `render.ts`.
- `application/concept-app.ts`: use cases, task handlers, approval handler, inbound handler, idle sweep. `prompts.ts`: templates `concept_partner.concept_turn@0.1.5`, `concept_partner.import_concept@0.1.0`, `continuity_editor.check_concept_brief@0.1.0`.
- `application/turn-stream.ts`: in-process pub/sub of live replies (per session; one live turn, late-join snapshot). `domain/partial-json.ts`: reads `reply_text` out of a streaming JSON prefix (escapes / `\uXXXX` / surrogate pairs decoded only once complete, so the text only grows).
- `adapters/db/repository.ts`, `adapters/http/routes.ts`, `adapters/http/stream-route.ts` (SSE).

## Behaviour notes
- The code decides which slot to ask (3.5); the model only phrases it and proposes slot updates. With an empty model proposal (or the llm module as a placeholder) the deterministic commit still runs the whole conversation: answers to the asked slot become `user_stated` (quote = message), seed chips → `user_stated`, model candidates → `agent_proposed_accepted`.
- CQ-01 (opening question) is a deterministic **system** message created with the session (no model call).
- Working brief jsonb = `{content, field_provenance, change_proposals, checks, meta}`; `ConceptBrief.content` = content + `field_provenance` + `contribution_summary` + `checks`.
- Titles (설계 추가): novels are created without a title (`제목 미정`, title_source=provisional). Every turn may return `working_title` (preview, title_source=auto) and `title_suggestions` (3–5, cleaned/deduped by `domain/title.ts`; fewer than 3 usable → ignored), stored in `meta.title_suggestions` while the title is not user-confirmed. "다른 추천 받기" = `concept_turn` with `input.titles=true` (cycle_key `titles:<sessionId>`, template `concept_partner.suggest_titles@0.1.0`, zod `TitleSuggestions`): no reply message, no turn count, cost added to the session; pending/failed state in `meta.title_refresh`. Choosing/editing a title = brief `title` (user_edited) → novel title_source=user, kept by approval (N2). On a messenger channel the turn reply lists the new suggestions as text.
- Live replies (설계 추가): `concept_turn` passes `onStream` to `ModelCallPort.call`; the raw JSON deltas go through `createFieldStreamer("reply_text")` into the hub (`begin` → `delta`… → `reset` on a gateway retry/repair or a thrown attempt → `done {messageId}` after the commit / `error` on the failure notice). The prompt asks for `reply_text` as the first key. Only the validated, committed message is persisted; the live text is display only (the persisted body may differ: option lines and title notes are added, and when the model asked a different slot than the code selected (3.5) the code's question replaces its reply — the live bubble is then replaced on `done`). Title refresh, import and check tasks do not stream. Messenger (Telegram) stays non-streaming.
- One turn at a time on the web (설계 추가): `POST …/messages` from the web route sets `rejectWhileTurnInFlight` → 409 `concept_turn_in_flight` while the session's in-flight task is queued/running (a stale id of a finished task does not block). Messenger messages keep X-7 (queued; the running reply is marked superseded). `POST …/stop-turn` cancels the in-flight task (running → dropped at its next safe point before commit; the model call itself is not aborted), clears `inFlightTaskId`, leaves a notice and ends the stream with `done {messageId:null}`. A run that ends without its commit for any other reason (task-board cancel, novel pause, lease lost, budget block, retry, commit rollback) goes through the engine's `onUncommitted` hook: the spent model cost is added to the session's `spentMicros`, a task that is over clears `inFlightTaskId` and ends the stream (`done` null), a task that runs again resets the live text and the stream waits for the next run. The SSE route also ends a stream whose session has no queued/running turn any more (after one grace tick). A cancel that lands after the last safe point is still honoured at the commit (the engine re-checks `cancel_requested` on the locked task row); `stopTurn` locks task → session like the commit.
- Change proposals (`domain/change-proposals.ts`, 설계 추가): at most one `pending` proposal per field (a newer one supersedes the old → `superseded/replaced`); every new proposal stores `base_value`. A proposal leaves `pending` by the user's decision (button, a quote-verified `proposal_decisions` entry from the model, or a plain yes/no text reply to the proposal question — that reply is never stored as the field value) → `accepted`/`rejected`; or, after a turn/import/form edit, by reconciliation: the field now holds the proposed value (user-backed origin → `accepted` applied_in_chat/form_edit, else `superseded/already_applied`) or moved away from `base_value` → `superseded/field_changed`. Each settlement is audited as `concept_brief.change_proposal_decided` (`after.decision/resolution/via`). The turn prompt lists pending proposals with ids. The web shows only pending ones; settled ones are in a collapsed "처리된 제안" list.
- 자동 승인 모드 (`domain/auto-approve.ts`, 설계 추가): per-session toggle in `working_brief.meta.auto_approve` (no column; audited as `concept_session.auto_approve_changed`, visible in every tab through SessionView `autoApprove`). While on, every turn commit (and import commit) answers the partner's latest prompt on the user's behalf in the same transaction — a user-side `option_pick` message with `concept_messages.auto_approved=true` (migration 0009), body `자동 승인: …`, authored by the delegating user — and queues the next turn (no browser needed, crash-safe: reply + pick + next task commit together, one pick per prompt). Choice order: pending change proposal (auto-accept → `accepted/auto_accepted`, via `auto_approve`; on a user-written field only with `accept_user_field_proposals`, default off → wait) → conflict/flip (wait) → reconfirm `@confirm_field` → the recommended option (none marked → `[추천해 줘]` once per slot, then the first agent/seed option) → `@to_confirming` → `[모두 확정]`/`[승인 요청]` cards = complete (컨셉 확정 stays manual) → open question without options = wait for the user. Values picked this way are `agent_auto_accepted` (confirmed; audited per commit as `concept_brief.auto_accepted`); an auto pick never overwrites `user_stated`/`user_edited` (becomes a change proposal). Stops: completed, `max_steps` (default 20), turn cap, budget (session pauses), model error / cancelled run, `stop-turn`, toggle off, session leaving `active`, messenger channel. While on, web `POST …/messages` during a turn is queued (201, X-7 path like proposal decisions) instead of 409; with the mode off the 409 lock is unchanged. The turn prompt (`@0.1.4`+) always asks for 2–3 options with one `is_recommended` and tells the model auto messages are not user evidence (the guard also ignores them as quotes).
- 대화 종료 = 브리프 완성 (설계 변경): the chat is driven by brief completeness, not a fixed turn count. While required fields remain the partner keeps asking (3.5); once every required field is confirmed `selectNext` returns `ready` and the reply is a closing summary (`summaryText`) + `READY_TEXT` ([승인 요청] guidance) with only the `[승인 요청]` control — no new question (prompt `@0.1.5` tells the model to return no questions then). Auto-approve stops there too (`completed`); 컨셉 확정 stays manual. `concept.max_turns` (default 200, was 40) is only a hidden safety ceiling: the web header shows required-field progress, not the turn count; the warning appears only within `concept.turn_soft_warning_remaining` (20) turns of the ceiling while required fields remain; hitting it leaves `turnCapText` (remaining field names + how to continue: `[50턴 더]` / '진행 방식 바꾸기' → 대화 안전 상한 올리기, `concept.turn_extension` 50 × `concept.max_turn_extensions` 4, or [전부 맡기기] / [폼으로 마저 입력]). The budget cap (`concept.session_budget_usd`) is unchanged. Migration 0010 raises `turn_limit` of open sessions created under the old 40 default.
- Turn reservation estimate for INV-CON-09: `TURN_RESERVE_MICROS` (0.15 USD, assumption) + `concept.check_reserve_usd`.
