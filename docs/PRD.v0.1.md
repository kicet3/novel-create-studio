## 1. 개요

### 1.1 한 줄 정의
사용자가 정한 목표에 맞춰 AI 에이전트 팀이 웹소설을 자율적으로 기획하고 연재합니다. 필요한 결정은 Discord나 Telegram으로 사용자에게 묻고, 세계관 온톨로지(Graph DB)로 설정 일관성과 떡밥(복선) 설치·회수를 관리합니다.

### 1.2 배경과 문제
1. **장편 연재는 일관성을 유지하기 어렵습니다.** 웹소설은 수백 화 단위로 연재되고, 공개된 회차는 사실상 고칠 수 없습니다. 초반 복선을 잊고, 인물마다 아는 정보가 다르고, 회귀·루프물에서는 같은 사건이 여러 시간선에 존재합니다. 장편을 "제대로 끝내는 것"이 가장 어렵다는 작가 회고가 있습니다 [2차]. 설정 붕괴나 떡밥 미회수를 정량화한 조사는 찾지 못했습니다 [미확인].
2. **연재 주기가 빠듯합니다.** 유료 연재 1화는 공백 포함 약 5,000~5,500자가 관행입니다 [2차]. 일일 연재 관행은 출처를 확보하지 못했지만 [미확인], 하루 1화 이상을 버틸 수 있는 생산 능력이 필요하다고 판단합니다(가정).
3. **기존 AI 글쓰기 도구는 대화형 보조에 머뭅니다.** 사람이 매번 프롬프트를 넣어야 하고, 작품 단위의 장기 기억(세계관, 떡밥, 공개 이력)을 구조화해 보관하지 않습니다(가정: 경쟁 제품은 상세 조사하지 않음).
4. **자율 에이전트는 사람의 판단을 받을 통로가 필요합니다.** 사용자가 대시보드 앞에 계속 앉아 있지 않으므로, 이미 쓰는 메신저로 짧게 묻고 답을 받아 반영해야 합니다.
5. **AI 생성물에는 정책과 법적 제약이 있습니다.** 일부 국내 플랫폼과 공모전은 AI 작품을 제한하고 [2차], 사람의 창작적 기여 없이는 저작권 보호를 장담할 수 없습니다 [2차]. 사람이 언제 무엇을 결정하고 고쳤는지 기록이 남아야 합니다.

### 1.3 제품 비전
- **작품을 "운영"하는 스튜디오**: 사용자는 쇼러너(총괄 PD) 역할을 합니다. 방향, 승인, 예산을 정하고, 에이전트 팀이 기획 → 집필 → 검수 → 연재를 반복합니다.
- **세계관이 살아 있는 데이터**: 인물, 장소, 사건, 규칙, 떡밥, 인물별 지식 상태를 시점과 버전이 있는 그래프로 관리합니다. 집필, 검수, 미디어 생성이 모두 이 그래프를 단일 원천으로 씁니다.
- **사람 개입은 적게, 기록은 확실하게**: 되돌릴 수 없거나 영향이 큰 결정만 묻습니다. 모든 결정, 승인, 수정은 감사 로그에 남겨 고지 의무와 저작권 주장의 근거로 씁니다.
- **텍스트에서 미디어로**: 완성된 화를 씬 단위로 나눠 삽화, 숏폼 트레일러, 핵심 씬 영상으로 확장합니다. 캐릭터 외형도 같은 온톨로지에서 가져와 시각 일관성을 유지합니다.

## 2. 목표와 비목표

### 2.1 목표
아래 수치는 초기 목표입니다. 가정: 기준 측정 전이므로 MVP 내부 검증(dogfooding) 후 다시 정합니다.

| ID | 목표 | 측정 기준 | MVP 목표치 |
|---|---|---|---|
| G-1 | 사용자 목표만으로 연재가 굴러간다 | 기획 확정 후 사람이 직접 쓰지 않고 생성·승인된 연속 화 수 | 30화 이상 연속 생성 (가정) |
| G-2 | 연재 속도를 유지한다 | 자율 모드에서 1화 생성~검수 완료 소요 시간(사람 대기 제외) | 중앙값 60분 이하 (가정) |
| G-3 | 설정 일관성을 지킨다 | 사람 검토에서 확인된 연속성 오류 수 / 화 | 0.3건/화 이하 (가정) |
| G-4 | 떡밥을 회수한다 | 기한이 지난 떡밥 중 회수 또는 의도적 폐기로 처리된 비율 | 90% 이상 |
| G-5 | 사람 개입을 줄이되 통제는 유지한다 | 화당 차단형 질문 수 / 질문 응답 후 반영 성공률 | 화당 차단형 1건 이하 / 반영 성공 100% |
| G-6 | 비용을 예측하고 통제한다 | 예산 하드 한도 초과 발생 건수 | 0건 (한도 도달 시 자동 일시정지) |
| G-7 | 사람 기여를 증명할 수 있다 | 회차별 사람 결정·수정 기록 내보내기 가능 비율 | 100% |
| G-8 (확장) | 씬 미디어를 저비용으로 만든다 | 채택된 삽화 1장당 비용(재시도 포함) | 0.5 USD 이하 (가정) |

### 2.2 비목표
- **국내 주요 플랫폼 투고 대행**: 플랫폼 업로드 자동화와 투고 대행은 하지 않습니다. 정책 충돌 위험이 크기 때문입니다(10절).
- **AI 탐지 회피**: AI 생성 사실을 숨기거나 탐지를 우회하는 기능은 만들지 않습니다.
- **독자용 연재 플랫폼**: 독자 커뮤니티, 결제, 랭킹은 범위 밖입니다.
- **실존 인물 기반 창작과 실사 얼굴 합성**: 기본으로 막습니다.
- **웹툰 자동 제작(MVP~v2)**: 말풍선, 컷 분할, 수십 컷 단위 일관성이 필요해 v2 이후 후보로 둡니다.
- **자체 모델 학습과 GPU 운영(MVP~v1)**: LoRA, 자체 호스팅 영상 모델은 후속 옵션으로 둡니다.
- **카카오톡 채널(MVP)**: 봇이 먼저 보내려면 사업자 인증과 유료 Event API가 필요합니다 [1차].
- **Paperclip 코드베이스 직접 포크**: 패턴과 범용 인프라를 참고할 뿐, 그 도메인(AI 회사 운영)을 그대로 가져오지 않습니다(14.2절).

## 3. 대상 사용자와 페르소나

가정: 1차 타깃은 개인 사용자의 로컬 또는 자체 호스팅 환경입니다(13절 D-1, D-2).

### P1. 실험형 창작자 "민준" (1차 타깃)
- 30대 개발자. 웹소설 독자이며 AI 도구에 익숙합니다.
- 목표: 머릿속 설정으로 장편을 끝까지 완성해 보고, 자체 채널이나 해외 플랫폼에 AI 생성 고지를 붙여 올립니다.
- 불편: 직접 쓰기에는 시간이 없고, 대화형 AI로는 50화쯤에서 설정이 무너집니다.
- 기대: 퇴근길에 Telegram으로 질문 2~3개에 답하면 다음 날 아침 새 화가 준비되어 있습니다.

### P2. 현업 작가 "서연" (작가 보조 용도)
- 로판 유료 연재 작가. 주 5회 이상 연재합니다(가정).
- 목표: 직접 집필은 유지하면서 설정 관리, 떡밥 추적, 초고·다음 화 기획 보조를 받습니다.
- 불편: 200화가 넘으면서 인물별 비밀과 복선 회수 시점을 엑셀로 관리하고 있습니다.
- 기대: 공동 집필 모드에서 본인이 쓴 원고를 온톨로지에 반영하고, 모순과 미회수 떡밥을 미리 경고받습니다. 플랫폼 AI 정책 때문에 본문 자동 생성은 끄고 쓸 수 있어야 합니다.

### P3. IP 기획자 "도윤" (확장 기능 사용자)
- 소규모 콘텐츠 스튜디오 PD.
- 목표: 원고에서 핵심 씬을 골라 삽화, 숏폼 트레일러, 피칭용 키비주얼을 빠르게 만듭니다.
- 불편: 캐릭터 외형이 컷마다 달라지고 영상 비용을 예측할 수 없습니다.
- 기대: 실행 전 비용 견적과 승인 게이트, 캐릭터 시트 기반 일관성, 모델 교체에 흔들리지 않는 프롬프트 자산.

## 4. 핵심 개념과 용어

| 용어 (식별자) | 정의 |
|---|---|
| 작품 (`Novel`) | 최상위 단위입니다. 세계관, 목표, 원고, 예산, 채널 연결, 감사 로그가 모두 작품에 속합니다. Paperclip의 Company(테넌트 루트)에 해당합니다. |
| 목표 (`Goal`) | 작품이 달성할 결과입니다. 장르, 분량, 화수, 결말 방향, 연재 주기, 비축분, 예산을 담습니다. 모든 작업은 목표까지 "왜 하는가" 체인으로 이어집니다. |
| 기획서 (`SeriesBible`) | 시놉시스, 로그라인, 주요 인물, 세계 규칙, 아크 구성을 담은 문서입니다. 사람이 승인하면 캐논이 됩니다. |
| 아크 (`Arc`) | 여러 화로 이루어진 이야기 단위입니다. 목표, 갈등, 결말 조건을 가집니다. |
| 화 (`Episode`) | 연재 단위입니다. 글자 수 목표, 회차 말 훅, 상태(`planned → outlining → drafting → reviewing → approved → published`)를 가집니다. |
| 씬 (`Scene`) | 화 안의 연속된 시공간 단위입니다. 등장 엔티티, 장소, 작중 시점, 원문 위치를 가지며 미디어 확장(샷, 프롬프트, 에셋)의 기준 단위입니다. |
| 샷 (`Shot`) | [확장] 씬을 영상·이미지로 표현하기 위한 카메라 단위입니다. 영상 클립 하나는 4~15초가 현실적 상한이라 씬은 여러 샷으로 나눕니다 [2차]. |
| 에이전트 역할 (`AgentRole`) | 에이전트의 책임 범위입니다. 4.1절을 참고합니다. |
| 작업 (`Task`) | 에이전트에게 할당되는 업무 항목입니다. 담당자는 하나이고 원자적으로 잠급니다(Paperclip의 Issue와 checkout 패턴). |
| 실행 (`Run`) | 에이전트가 한 번 깨어나 작업을 수행하는 단위입니다. 비용과 로그를 기록합니다. |
| 질문 (`Question`) | 에이전트가 사람에게 묻는 1급 객체입니다. 등급(차단형 `blocking`, 비차단형 `non_blocking`, 정보성 `informational`), 유형, 추천안, 근거, 마감, 상태를 가집니다. |
| 채널 (`Channel`) | 질문과 알림을 주고받는 외부 메신저 연결입니다(Discord, Telegram 등). 채널 중립 질문 모델을 어댑터가 각 메신저 UI로 바꿉니다. |
| 승인 (`Approval`) | 진행 전 사람의 결정이 필요한 게이트입니다(기획서 확정, 화 승인, 예산 초과, 캐논 변경 등). |
| 자율성 수준 (`AutonomyLevel`) | 사람 개입 정도를 정하는 작품 설정입니다(6.3절). |
| 세계관 온톨로지 (`WorldOntology`) | 인물, 장소, 조직, 사물, 사건, 규칙, 관계, 인물별 지식을 그래프로 표현한 작품별 지식 저장소입니다. 사실마다 시점, 시간선, 출처, 캐논 상태를 가집니다. |
| 사실 (`Fact`) | 온톨로지의 최소 주장 단위입니다. 예: "A는 3화 시점에 B의 정체를 모른다". |
| 시간선 (`Timeline`) | 회귀·루프·평행세계를 표현하는 사실의 유효 범위입니다. |
| 캐논 (`Canon`) | 작품에서 확정된 사실 집합입니다. 상태는 `draft`(초안), `approved`(승인, 변경 시 승인 필요), `published_locked`(공개 회차에 나온 사실, 변경 불가. 바꾸려면 명시적 리트콘 승인)입니다. |
| 떡밥 (`Setup`) / 회수 (`Payoff`) | 복선 설치와 회수입니다. 떡밥은 `planted → reinforced → paid_off` 또는 `abandoned` 상태와 회수 기한을 가지며, 관련 화·씬·사실과 연결됩니다. |
| 연속성 이슈 (`ContinuityIssue`) | 생성 원고와 캐논이 충돌하는 후보입니다. 심각도, 근거 사실, 처리 상태를 가집니다. |
| 플랫폼 프로필 (`PlatformProfile`) | 글자 수 기준(공백 포함·제외), 최소 회차, 일일 업로드 상한, AI 정책 메모, 확인일을 담은 프리셋입니다. |
| 예산 (`Budget`) / 비용 이벤트 (`CostEvent`) | 작품·아크·기능별 한도와 실제 비용 원장입니다. 소프트 경고와 하드 한도 자동 일시정지가 있습니다. |
| 감사 로그 (`ActivityLog`) | 상태를 바꾸는 모든 동작의 기록입니다. 주체(사람, 에이전트, 시스템), 대상, 이전·이후 값, 근거를 남깁니다. |
| 미디어 에셋 (`MediaAsset`) | [확장] 생성된 이미지·영상과 그 출처 기록(모델 ID, 버전, 파라미터, 프롬프트, seed, 레퍼런스, 비용, AI 생성 표시)입니다. |
| 씬 프롬프트 (`ScenePromptIR`) | [확장] 모델 중립 중간 표현입니다. 등장 엔티티, 장소, 소품, 카메라, 분위기, 대사, 시점별 외형을 구조화 필드로 담고, 실제 프롬프트는 공급자 어댑터가 렌더링합니다. |
| 시각 자산 (`VisualReference`) | [확장] 온톨로지 엔티티에 연결된 캐릭터 시트, 승인된 레퍼런스 이미지, 시점별 외형 변화입니다. |
| 공급자 프로필 (`ProviderProfile`) | LLM·이미지·영상 공급자의 모델 목록, 가격, 상업 이용 조건, 콘텐츠 제한, 종료 예정일입니다. |

## 5. 사용자 시나리오와 여정

### 5.1 작품 생성
1. 민준(P1)이 새 작품을 만들고 장르 템플릿 "현대판타지 회귀물"을 고릅니다.
2. 목표를 입력합니다: 전체 120화, 플랫폼 프로필 "기본(공백 포함 5,000~5,500자)", 하루 1화, 비축분 5화, 결말 방향 "주인공이 회귀 원인을 끊는다", 월 예산 상한.
3. 자율성 수준을 고릅니다. 기본값은 "화별 승인"입니다.
4. Telegram을 연결합니다. 화면의 일회용 deep link를 열고 `/start`를 누르면 채팅이 작품에 바인딩됩니다.

### 5.2 기획 확정
1. `planner`가 로그라인 후보 3개를 만들고, `showrunner`가 Telegram 버튼 질문으로 보냅니다(차단형).
2. 민준이 2번을 고르고 "여주는 회귀 사실을 늦게 알아야 함"을 서술형으로 덧붙입니다.
3. `planner`가 기획서(인물, 세계 규칙, 회귀 규칙, 아크 4개)를 만들고, `world_keeper`가 초기 온톨로지를 구축합니다.
4. 민준이 대시보드에서 기획서와 온톨로지 요약을 보고 일부를 고친 뒤 승인합니다. 승인한 사실은 `approved` 캐논이 됩니다.

### 5.3 자율 연재
1. `showrunner`가 1아크를 화 작업으로 나누고 `foreshadow_manager`가 떡밥 배치 계획을 붙입니다.
2. 화마다 아웃라인 → 초고 → 연속성 검사 → 문장·분량 검수 → 사람 승인 순서로 진행합니다.
3. 승인된 화가 비축분에 쌓이고, 사용자가 "공개 처리"하면 그 화의 사실이 `published_locked`가 됩니다.

### 5.4 메신저 질문 응답
1. 12화 집필 중 `writer`가 "조연 C를 여기서 죽일지"를 결정하지 못합니다. 결말에 영향이 있으므로 차단형 질문이 됩니다. 추천안, 근거, 마감 시각이 붙습니다.
2. 같은 시간 창의 비차단형 질문 2개(조연 이름, 지명)는 digest 한 통으로 묶여 갑니다. 비차단형은 추천안으로 먼저 진행합니다.
3. 방해금지 시간이 끝난 오전 8시에 메시지가 도착합니다. 민준이 버튼으로 "살린다"를 고릅니다.
4. 답변은 질문 ID, 영향받는 작업, 온톨로지 노드에 연결되어 감사 로그에 남고, 12화 작업이 재개됩니다. 다른 화 작업은 그동안 멈추지 않았습니다.
5. 비차단형 질문에 늦게 답해 추천안과 다른 답이 오면, 해당 화가 공개 전이면 수정 작업이 생기고, 공개 후면 리트콘 승인 질문이 생깁니다.

### 5.5 떡밥 회수
1. 5화에 설치한 "주인공 손목의 흉터" 떡밥의 회수 기한이 40화입니다.
2. 35화 기획 시 `foreshadow_manager`가 회수 후보 씬을 제안하고, 기한이 지나면 대시보드와 digest에 경고가 뜹니다.
3. 38화에서 회수하면 떡밥이 `paid_off`가 되고 관련 화·씬·사실이 연결됩니다. 회수 리포트에서 미회수·기한 초과 떡밥을 확인할 수 있습니다.

### 5.6 씬 미디어 생성 [확장]
1. 도윤(P3)이 완결된 1아크에서 핵심 씬 5개를 고릅니다.
2. `scene_director`가 씬을 샷으로 나누고 `ScenePromptIR`을 만듭니다. 등장 인물의 해당 시점 외형(의상, 부상)은 온톨로지에서 가져옵니다.
3. 주요 인물의 캐릭터 시트를 먼저 생성하고 도윤이 승인합니다. 승인된 시트가 이후 생성의 레퍼런스가 됩니다.
4. 저해상도 초안 이미지를 만들고, 승인된 컷만 고해상도로 다시 생성합니다.
5. 30초 9:16 숏폼 트레일러를 만들기 전, 예상 비용이 Discord로 승인 요청됩니다. 승인하면 키프레임 이미지를 I2V로 영상화하고 이어 붙입니다.
6. 필터에 막힌 샷은 실패 결과로 기록되고, 순화안과 생략 중 무엇을 할지 질문이 옵니다.
7. 결과물에는 AI 생성 메타데이터와 출처 기록이 붙습니다.

## 6. 기능 요구사항

우선순위: **P0** = 해당 릴리스의 필수, **P1** = 중요(다음 릴리스로 미룰 수 있음), **P2** = 선택. 확장 영역(6.10~6.13)의 우선순위는 해당 확장 릴리스(v1/v2) 안에서의 우선순위입니다.

### 6.1 작품·목표 설정

| ID | 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|

추가로 공모전의 "AI 사용 시 당선 취소" 문구가 늘고 기준이 모호하다는 비판이 있고, AI 사용이 드러난 작품에 별점 테러 같은 독자 반발도 있었습니다 [2차].

**제품 결론**
- "완전 자율 생성 후 국내 주요 플랫폼 투고"는 현재 정책과 충돌할 위험이 큽니다. 투고 자동화는 비목표입니다(2.2절).
- 플랫폼·공모전 프로필은 데이터로 관리하고 확인일과 출처를 함께 저장합니다(FR-NOV-04).
- `co_writing` 모드를 두어 본문을 사람이 쓰고 에이전트가 기획·검수·온톨로지만 맡는 사용도 지원합니다. 다만 이 모드가 특정 플랫폼 정책을 충족하는지는 플랫폼마다 판단이 다르며 제품이 보장하지 않습니다.

### 10.2 저작권
- **한국**: 문체부·한국저작권위원회 생성형 AI 저작권 안내서(2023-12-27)에 따르면, 인간의 창작적 개입이 없는 AI 산출물은 저작권 등록 대상이 아니고, 등록 시 AI 산출물과 인간 창작 부분을 구분해 적어야 하며 허위 기재는 처벌받을 수 있습니다. AI는 저작자가 될 수 없습니다 [2차]. 2025-06 '생성형 AI 활용 저작물 등록 안내서'는 원문 미확인입니다.
- **미국**: 저작권청 보고서 Part 2(2025-01-29)는 프롬프트만으로는 보호받지 못하고, 사람의 표현적 입력이 지각 가능하게 남은 부분과 사람의 선택·배열·수정은 보호될 여지가 있다고 봤습니다. 대법원은 2026-03-02 Thaler v. Perlmutter 상고를 기각해 인간 저작자 요건이 유지됐습니다 [2차].
- **제품 반영**: 완전 자율 원고의 저작권 보호를 장담할 수 없다는 점을 `full_auto` 선택 시 고지합니다. 사람 기여 리포트(FR-HIL-05)로 사람이 쓴 부분, 수정, 결정 기록을 내보냅니다. 이 기록이 법적 효력을 보장하지는 않는다는 점도 함께 고지합니다.

### 10.3 AI 생성 고지와 표시
- **한국 AI기본법(2026-01-22 시행)**: 생성물 표시 의무는 AI 사업자에게 있고, 딥페이크성 생성물은 명확히 표시해야 하며, 서비스 밖으로 내보낼 때는 워터마크가 필요하고 기계 판독형 비가시 워터마크도 허용된다는 해설이 있습니다. 이용자에게는 의무가 없다는 해설도 있습니다. 과태료는 최대 3천만 원이라는 보도가 있고, 계도 기간과 시행령 세부 의무는 미확인입니다 [2차].
- **제품 반영**: 제품을 서비스로 제공하면 우리가 의무 주체가 될 수 있습니다(가정: 로컬 자체 호스팅만 제공해도 해당하는지는 법률 검토 필요, D-12). 이미지·영상 내보내기에 AI 생성 메타데이터를 기본 삽입하고(FR-IMG-06), 원고 내보내기에 고지 문구를 기본 포함합니다(FR-MAN-05). Veo 결과물에는 SynthID가 자동 삽입된다는 보도가 있습니다 [2차].

### 10.4 미디어 모델 이용약관과 콘텐츠 제한
- **인물 생성 제한**: Veo 3.1은 I2V, 보간, 레퍼런스 모드에서 `allow_adult`만 허용해 레퍼런스 기반 미성년 인물 생성이 안 되고, EU·UK·스위스·MENA에서는 모든 모드가 `allow_adult`로 제한됩니다 [1차]. 학원물·아동 캐릭터 영상화가 막힐 수 있습니다.
- **실존 인물**: 주요 공급자 정책은 실존 인물 사칭과 동의 없는 합성을 금지합니다(정책 원문은 이번 조사에서 다시 확인하지 않음). Seedance 2.0은 실사 얼굴 레퍼런스를 차단한다고 합니다 [2차].
- **선정성·폭력**: 상용 API는 노골적 성적 콘텐츠를 일반적으로 금지하고 과도한 폭력을 필터링합니다. 안전·기억 필터로 결과가 차단될 수 있습니다 [1차, Veo].
- **상업 이용**: FLUX.2 [dev] 가중치는 비상업 라이선스이고 출력물의 상업 이용 해석은 출처마다 다릅니다. LTX(OpenRAIL), HunyuanVideo(EULA)는 라이선스 제약 확인이 필요합니다. Wan 2.2는 Apache 2.0입니다 [2차].
- **학습 데이터 분쟁**: MPA와 할리우드 스튜디오가 Seedance에 저작권 침해 경고장을 보냈다는 보도가 있습니다 [2차]. 공급자 선정 시 검토 항목으로 둡니다.
- **제품 반영**: 공급자 프로필(FR-IMG-08, FR-VID-06)에 상업 이용 조건, 인물·지역 제한, 종료 예정일을 담고, 생성 전에 검사합니다.

### 14.2 Paperclip 참고 범위

Paperclip은 AI 에이전트를 하나의 "회사"로 조직해 운영하는 제어 평면입니다. 목표 계층, 작업 할당, 예산, 승인, 감사 로그를 관리하고 에이전트는 어댑터로 깨어나 결과를 보고합니다. 참고 맵: `/private/tmp/claude-501/-Users-snowfall-orca-projects-rea-rea/f618b7ed-232a-40d9-a19b-357147a8e7b1/scratchpad/paperclip-architecture-map.md` (1절 제품 개념, 8절 재사용 판단표).

**개념 매핑**

| Paperclip | novel-create-studio | 비고 |
|---|---|---|
| Company (테넌트 루트) | `Novel` | 모든 데이터와 예산을 작품 단위로 격리 |
| Goal → Project → Issue 계층, "because" 체인 | `Goal` → `Arc` → `Episode` → `Scene`/`Task` | 모든 작업은 목표로 이어짐(FR-AGT-01) |
